# MODO_USO.md

## Objetivo

El Modo Uso es la interfaz que utiliza directamente la persona que necesita comunicarse.

Debe ser la experiencia más simple, accesible y predecible del sistema.

## Criterios validados

Los siguientes criterios fueron validados con una profesional de educación especial y se desarrollan en las secciones de este documento:

- 6 opciones como base inicial adecuada;
- los pictogramas requieren entrenamiento previo;
- estabilidad visual y posicional;
- texto hablado de 3–4 palabras como máximo cuando sea posible;
- personalización según necesidades, contexto, recursos, funcionamiento, intereses, gustos y motivaciones;
- posibilidad de múltiples tableros;
- tablet como dispositivo prioritario y mobile como adaptación posterior.

## Principio principal

> Una necesidad frecuente debe poder comunicarse con un solo toque siempre que sea posible.

Ejemplo:

```text
[ pictograma de baño ]
QUIERO IR AL BAÑO
```

Al tocar:

```text
feedback visual
→ reproducción inmediata
→ estado normal
```

No requiere confirmación ni botón adicional para hablar.

## Tarjetas

Cada tarjeta puede tener:

- pictograma;
- texto visible;
- texto hablado.

Ejemplo:

```text
Pictograma:
baño

Texto visible:
BAÑO

Texto hablado:
Quiero ir al baño
```

El texto visible puede ser más corto que el texto reproducido.

### Texto hablado

El texto hablado debe tener como máximo 3–4 palabras cuando sea posible.

Frases cortas son más fáciles de asociar al pictograma, de recordar y de imitar.

Ejemplos:

```text
Quiero ir al baño   ✔
Tengo hambre        ✔
Necesito ayuda      ✔
Por favor, ¿me podrías acompañar al baño ahora?   ✘
```

## Primera experiencia

Para usuarios con comunicación emergente, comenzar con pocas opciones grandes.

6 opciones es una base inicial adecuada.

Ejemplo:

```text
┌──────────────┬──────────────┐
│    BAÑO      │    HAMBRE    │
├──────────────┼──────────────┤
│  NO QUIERO   │  ME MOLESTA  │
├──────────────┼──────────────┤
│    TOMAR     │    AYUDA     │
└──────────────┴──────────────┘
```

La cantidad de opciones debe poder aumentar según las necesidades de cada usuario.

## Entrenamiento previo

Los pictogramas no son autoexplicativos: requieren entrenamiento previo con la persona usuaria.

La aplicación es un apoyo para ese proceso, no lo reemplaza.

Implicancias:

- el significado de cada pictograma se enseña y se practica antes o durante el uso;
- un pictograma aprendido no debe cambiarse sin una decisión del profesional o la familia;
- incorporar opciones nuevas de forma gradual, acompañando el entrenamiento.

## Personalización

Cada tablero debe poder adaptarse a la persona usuaria según:

- necesidades;
- contexto;
- recursos disponibles;
- funcionamiento;
- intereses;
- gustos;
- motivaciones.

La personalización la realiza el terapeuta o la familia desde la configuración, nunca desde el Modo Uso.

## Navegación

Evitar navegación profunda.

Cuando existan muchas opciones pueden utilizarse categorías, por ejemplo:

- Necesidades;
- Personas;
- Comida;
- Actividades;
- Emociones;
- Lugares.

La cartilla principal debe ser la primera experiencia disponible.

### Múltiples tableros

Una persona usuaria puede tener más de un tablero, por ejemplo para distintos contextos o actividades.

La cartilla principal sigue siendo la primera experiencia disponible.

El cambio entre tableros no debe agregar complejidad a la interacción principal de una necesidad → un toque.

## Estabilidad

La estabilidad es visual y posicional.

### Posicional

No reorganizar automáticamente las tarjetas.

Las posiciones aprendidas deben mantenerse estables siempre que sea posible.

No ordenar dinámicamente por frecuencia, predicción o uso reciente.

### Visual

Una vez aprendido, cada concepto debe mantener su apariencia:

- mismo pictograma;
- mismo texto visible;
- mismo tamaño y proporción de la tarjeta.

Los cambios visuales globales (tema, tipografía, disposición) deben ser deliberados y no frecuentes.

## Voz

Al tocar una tarjeta:

1. mostrar feedback visual;
2. cancelar audio anterior si es necesario;
3. reproducir el texto hablado;
4. volver al estado normal.

Evitar reproducción simultánea de varias frases.

## Diseño

Priorizar:

- pictogramas grandes;
- texto grande;
- alto contraste;
- espacios amplios;
- pocos elementos;
- navegación clara;
- touch targets grandes.

Evitar:

- elementos administrativos;
- configuraciones visibles;
- tablas;
- menús complejos;
- animaciones decorativas;
- exceso de colores;
- información secundaria.

## Dispositivo prioritario

La tablet es el dispositivo prioritario.

Diseñar primero para tablet en orientación horizontal.

Luego adaptar a:

- tablet vertical;
- desktop.

Mobile es una adaptación posterior y no condiciona las decisiones de diseño iniciales.

## Progresión

El sistema debe permitir aumentar progresivamente la complejidad:

```text
6 opciones
→ 9 opciones
→ 12 opciones
→ categorías
→ vocabulario más amplio
→ construcción de frases
```

Cada paso acompaña el entrenamiento de la persona usuaria; no se avanza solo por disponibilidad de la función.

La construcción de frases no forma parte de la experiencia inicial obligatoria.

## Validación

Antes de considerar terminado el Modo Uso, comprobar:

- una tarjeta puede activarse con facilidad;
- el audio se reproduce correctamente;
- taps rápidos no generan voces superpuestas;
- las posiciones se mantienen estables;
- la apariencia de cada tarjeta se mantiene estable;
- los textos hablados son breves (3–4 palabras cuando sea posible);
- los pictogramas no se deforman;
- existe fallback ante error de imagen;
- la interfaz funciona correctamente en tablet;
- no aparecen funciones administrativas.
